# 需求交付

目标：
$ARGUMENTS

## 链路

```text
对齐方案 -> 执行 -> 验证
```

## 1. 对齐方案
`product_aligner` / `gpt-5.6-sol`

1. 我只给目标；有飞书/文档/Figma/代码就自己读。
2. grill 对齐：一次只问 1 个决策问题，并给推荐答案。
3. 能代码/文档查到的事实自己查，不要问我。
4. 需要我拍板的决策才问；不确定就停在对齐，不擅自开做。
5. 有现成文档时优先 `grill-with-docs`；纯方案讨论可用 `grill-me` / `grilling`。
6. 对齐产出尽量短：目标、范围、关键规则、验收标准、待定项。未达成共识前不进入执行。

## 2. 执行
`implementer` / `grok-4.5`

1. 共识确认后再改代码。
2. 最小改动；默认独立 worktree。
3. 按仓库现有结构做，不扩 scope。
4. 中途发现新冲突，回到对齐，不硬做。
5. Push/PR 仅在目标已要求时做。

## 3. 验证
`verifier` / `gpt-5.6-terra`

1. 独立验证，不只复述执行自检。
2. focused 验证；后端尽量打真实接口/服务。
3. 对照验收标准逐项给证据。
4. 不够就说 blocked 和缺口，不装完成。
5. 高风险写先停：生产写库、回放、回填、停任务、改生产配置、Job 触发。

主会话可直接串完；只有换模型或上下文隔离有收益时再派子 agent。

## 输出

- 对齐结论 / 待确认项
- 改动说明
- 验证证据
- 风险 / 缺权限 / 待决策
