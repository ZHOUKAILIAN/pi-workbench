# 排查

目标：
$ARGUMENTS

## 链路

```text
现象 -> 问题 -> 根因 -> 修复 -> 验证
```

## 要求

1. 我只给目标；能自补的链接、仓库、日志、数据自己补。
2. 目标不清先问清：要交什么、怎样算做完。缺必要条件先对齐。
3. 一次只问 1 个最短阻塞问题；能自查的不问。
4. 查到底，给出可复核证据链：代码路径、日志/时间线、数据状态、反例。
5. 根因不停留在表面；后面还有原因就继续查，直到最根本且可验证。
6. 根因状态：已证实 / 未证实 / 阻塞。证据不足就说缺口，不硬修。
7. 目标清晰且条件足够时尽量闭环；本地可安全改就最小修复并验证，优先打根本原因。
8. 高风险写先停：生产写库、回放、回填、停任务、改生产配置、Job 触发。缺权限直接说。
9. Push/PR 仅在目标已要求时做。

## 子 agent（按需）

默认主会话可直接做完。需要阶段隔离或换模型时再派：

- 取证/下钻：`evidence_investigator`（`grok-4.5`；难收敛可升 `gpt-5.6-sol`）
- 修复：`implementer`（`grok-4.5`）
- 验证：`verifier`（`gpt-5.6-terra`）
- 若修复前出现产品冲突：`product_aligner`（`gpt-5.6-sol`）

## 输出

- 目标理解 / 待确认项（如有）
- 现象与问题
- 证据链
- 根因状态
- 改动与验证（如有）
- 风险 / 缺权限 / 待决策
