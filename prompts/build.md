# 需求交付

目标：
$ARGUMENTS

## 先定交付级别

只选择满足风险的最小级别：

| 级别 | 适用 | 阶段 |
| --- | --- | --- |
| `small` | 单点、规则明确、影响局部 | 主会话确认边界 -> 实现 -> 评审 -> focused 验证 |
| `standard` | 跨文件或用户可见行为变化 | 对齐 -> 实现 -> 评审 -> 独立验证 |
| `critical` | 共享逻辑、数据、权限、协议、迁移或高风险变更 | 对齐 -> 实现 -> 评审 -> 独立验证 |

不要因为模板存在就强制运行所有角色。主会话默认连续实现、自检和修复，所有 coding diff 保留独立 `code_reviewer`；对齐和验证按风险选择角色。`implementer` 仅用于契约明确、写入互不重叠、可独立验证且主会话能同时推进工作的并行子任务，或用户明确指定的执行者。规模大、文件多不是委派理由；每个 agent 必须提供独立价值。

## 任务契约

执行前形成一个短契约：

```text
目标：
仓库/分支/环境：
范围：
不改变的行为：
验收标准：
交付级别：small / standard / critical
待决策：无，或需要用户确认的单个问题
```

规则：

1. 能从飞书、文档、Figma、代码和测试查到的事实自行查，不问用户。
2. 只有产品语义、范围、写入目标、环境或验收标准仍有多个合理答案时才停住询问。
3. 用户说“先对齐”“先确认方案”时，输出契约后必须停在 `WAITING_FOR_USER_ALIGNMENT`；用户明确确认后才能执行。
4. 用户明确给出完整规则和验收标准时，不重复 grill 已经确认的内容。
5. 中途出现新冲突，退回对齐并只报告新增决策，不重新讨论全部方案。

## 阶段契约

### 对齐

输入：原始目标、已查到的事实和现有约束。

输出：已确认、推断、待确认、验收标准、继续前提。除非存在真实决策，否则不必单独派 `product_aligner`。

### 实现

输入：已确认任务契约。

要求：主会话直接实现并保留讨论上下文；最小改动；使用目标仓库现有结构；不做顺手重构；需要 worktree 时从目标仓库创建；Push/PR 仅在用户要求时做。实现前固定原始功能基准并确认已有工作区改动归属；已有部分实现时不能用当前 HEAD 隐去早期改动，不为评审制造提交。完整功能及相关成功/异常/取消/早退、共享调用方自检完成后集中送审，检查 mock/spy 和断言能排除错误实现。并行子任务先集成再整体评审。

输出：完整功能范围、原始基准、改动文件、行为变化、自检命令与结果、已确认决策和待独立验证项；复用已有定位作为导航，不另建交接文件。

### 评审

所有 coding diff 都交给 `code_reviewer` 做独立评审；纯文档和只读任务不强制。

输入：原始固定功能基准、完整任务契约、已确认用户决定、自检证据与未验证项。审完整功能最终状态及受影响的存量调用链，不只审最后补丁，不扩成无关全仓审计。明确 committed/working-tree/staged/combined 模式及比较语义；有中途提交时不能只审当前 HEAD 后的工作区，必要时明确要求原始基准直比当前状态并纳入相关新增文件。

先检查基准和范围，已知缺失时报告阻塞，不启动注定失败的调用。输出 Standards / Spec 两轴集中 findings、影响与关闭条件，以及 APPROVED / CHANGES_REQUESTED / BLOCKED。只有 CHANGES_REQUESTED 启动主会话集中修复相关问题并自检；BLOCKED 或工具失败先报告，APPROVED 不调用多余修复。复审传回原 reviewer 的 session 句柄并核对返回元数据；persistent: true 不是会话复用。补交最新修复、测试和用户决定，保留完整功能范围与原基准；句柄不可用时说明并完整交接。目标一轮完整首审加集中修复复审，不硬限轮数；额外问题说明首审遗漏、修复引入或范围变化。未复审通过的修复不算完成，批准不等于独立运行验收。

### 验证

所有代码交付都必须有验证，但验证 agent 不是强制的。简单改动可由主会话运行 focused check；需要独立判断、真实服务或多状态验收时使用 `verifier`。

输入：任务契约、改动摘要、自检结果。输出 `passed` / `failed` / `blocked` 以及逐项证据。

## 模型与配置

用户角色位于 Pi agent 目录的 `agents/*.md`（默认 `~/.pi/agent/agents`，可由 `PI_CODING_AGENT_DIR` 改写）；可信项目角色位于 `.pi/agents`。角色未指定 `model` 时，子进程使用 Pi 的默认模型设置，不保证跟随主会话临时切换。模型绑定在私有 local 配置的 `agentModels` 中维护并安装，不在 prompt 重复声明。模型失败时报告失败类型和阶段状态；未经允许不更换模型或退化执行。

## 最终输出

- 任务契约与交付级别
- 改动说明
- 评审结论（如适用）
- 验证证据
- 分支/提交/PR/部署状态（如适用；不每轮自动 commit，不单独委派一轮仅为提交，保留原始功能基准）
- 风险、缺权限和待决策
